# Daybook Cloud Setup

Daybook can run as a local demo or connect to a Supabase project for user accounts and cloud data.

## Configure Supabase

1. Create a Supabase project.
2. In the Supabase SQL Editor, run `supabase/schema.sql`.
3. For a local cloud test, set `url` to the project URL and `anonKey` to the project's publishable/anon key in `supabase-config.js`.
4. In Supabase Authentication settings, enable email/password sign-in and configure the site URL and allowed redirect URLs for your local and published HTTPS origins.
5. Serve the folder through a local web server or deploy it to an HTTPS static host. Supabase authentication does not work reliably from a `file://` URL.

The publishable/anon key is designed to be used in browser code. Never put a `service_role` key in this app. Row-level security in `supabase/schema.sql` restricts each signed-in user to their own records; keep those policies enabled.

## Local demo mode

Leave both values empty in `supabase-config.js` to use the sample workspace saved in this browser. Once both Supabase values are set, Daybook requires sign-in and reads/writes account data through Supabase instead of local browser storage.

When a signed-in account has no cloud records and this browser has saved workspace data, Daybook asks whether to import it. Accepting copies those records to the signed-in account; declining leaves the browser copy untouched and starts with an empty cloud workspace.

## Deploy with Netlify

1. Push the `Daybook` folder to a Git repository and import it into Netlify.
2. In Netlify site environment variables, set `DAYBOOK_SUPABASE_URL` to the Supabase project URL and `DAYBOOK_SUPABASE_ANON_KEY` to its publishable/anon key. These are public client values; never use the `service_role` key.
3. Deploy. `netlify.toml` runs `scripts/write-supabase-config.mjs`, which validates the HTTPS URL, generates `supabase-config.js` with `requireCloudAuth: true`, and fails the build if either variable is missing.
4. Copy the deployed HTTPS URL into Supabase Authentication's Site URL and allowed redirect URLs, then redeploy and test sign-up, confirmation, sign-in, password reset, and sign-out.

The checked-in `supabase-config.js` stays blank with `requireCloudAuth: false`, so opening the project locally continues to show demo mode. Production builds generated by Netlify require Supabase; they fail closed instead of showing the demo if the generated config is absent.

For other static hosts, provide the same two public values in that host's build process and set `requireCloudAuth: true` in its generated `supabase-config.js` before publishing.

## Before public launch

- Replace demo business/profile content and review all translations.
- Configure email confirmation, password reset, and production redirect URLs.
- Add a privacy policy, terms, a data export/deletion process, and a backup plan.
- Test two separate accounts to confirm they cannot access each other's data.
- Publish only over HTTPS and monitor authentication and database errors.
- Review privacy/terms with qualified counsel; this setup does not itself establish legal compliance.
- AI, calendar synchronization, and push/email reminders are not included in this cloud foundation.
